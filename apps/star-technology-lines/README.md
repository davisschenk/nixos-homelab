# Starline

Starline is a Vite app for planning [Star Technology](https://github.com/StarT-Dev-Team/Star-Technology) processing lines. Start with a Void Ore Extractor, sieve, or geode filtrator, set its voltage tier and machine count, and choose downstream recipes for each output. The planner sizes linked machines to the available throughput and totals expected output per minute. Lines are saved in your browser and can be imported or exported as JSON.

## Run the app

```sh
cd apps/star-technology-lines
npm install
npm run dev
```

`npm run build` creates a static site in `dist/`. The committed `public/catalog.json` is included in the build; no game installation or account is needed to browse it.

## Recipe data

The bundled catalog uses a `/kubejs export` from the running `1.20.1-THETA-1-HOTFIX-3` instance, matching the pack's [Theta 1 Hotfix 3 release tag](https://github.com/StarT-Dev-Team/Star-Technology/tree/26135f37ebad21800d7ffe61f29189d6f15254ab). The export captures final registered recipes, including recipes generated by GT and other installed mods after KubeJS modifications. It contains 38,236 GT recipes with complete, calculable inputs, outputs, duration, and EU/t. The build filters incomplete entries, so catalog search and stage suggestions use the same calculable set. Item tags from the export connect raw ores and other tagged inputs to their recipes. Voltage constants come from the [StarT GTM fork](https://github.com/StarT-Dev-Team/GTM-StarT-Fork/blob/a73acfa666ec53a8e9efd285a296b3b97546f100/src/main/java/com/gregtechceu/gtceu/api/GTValues.java). The pack's MIT license is included in [STAR-TECHNOLOGY-LICENSE](STAR-TECHNOLOGY-LICENSE).

The source importer remains available for source-only regeneration. It reads syntax trees without running modpack scripts and preserves unresolved fields for review. The runtime importer reads the exported JSON and item tags; it separates non-consumed meshes and circuits from consumed inputs and preserves chance and tier bonuses. Chance-based output rates are expected averages, and unlinked inputs are assumed supplied. Machine counts round up to cover the selected input rate. The **Macerate raw ores** action adds and sizes a standard macerator stage for every available raw ore output. Recipe selection remains available on each output for alternate paths.

To regenerate from a local checkout of the pack source:

```sh
npm run catalog:build -- --source-root /path/to/Star-Technology --pack-mode default --pack-version 1.20.1-THETA-1-HOTFIX-3 --kubejs-export /path/to/minecraft/local/kubejs/export
npm run catalog:check
npm test
```

Omit `--kubejs-export` to build the smaller source-only catalog. The committed catalog uses the in-game export. To update it, run `/kubejs export` in the matching pack instance and copy its `recipes` and `tags/minecraft` directories to the export path.

The catalog schema is versioned. Each adapter produces records with a `sourceId`, source metadata, and normalized recipe fields. The build command accepts `--json /path/to/another-catalog.json` to merge another catalog, then checks source IDs and recipe keys for collisions. The app loads the resulting static `catalog.json` at runtime, so it does not depend on a particular parser or data service.
